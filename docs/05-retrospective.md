# 开发复盘

## 难点

核心难点是分开模型建议与实际执行：模型可以安排多个工具、提出价格或声称成功，只有执行器确认的工具结果才能决定业务状态。模型负责观察后调整，程序维护费用、时间、依赖及保存门禁。

同一响应里预排的后续动作不能证明模型观察了前项结果。遇到失败或超限后跳过剩余调用，补齐全部工具结果再让模型决定，才能形成可检查的观察与调整关系。

## 实际发现与修正

- 首轮测试发现 Mock 用金额字符串与浮点数比较，引发错误；改为 Decimal 并重新验证。
- 精确截止边界发现已完成任务仍可能显示剩余保存耗时；完成状态的剩余必要费用和时间统一为 0，并增加断言。
- 真实超预算路径在调整到 8 后额外估算，最终为 9。完整保留该调用，而非修改记录使路径更理想。
- 依赖初次下载超时，重试官方源后成功；构建时确认 wheel 包含合成数据，避免安装包缺材料。
